# 学生交互优化实施清单

2026-09-30，依据教师反馈“操作太麻烦，学生不知道点哪里”优化现有四关。

## 诊断与选择

学生需要同时处理情境、预测、声音来源、操作、手动记录、三个流程节点、迁移选择与提交，界面负担较高；操作对象与记录按钮分离，结果出现后还要寻找保存入口。单纯增加闪烁仍要求学生在整页寻找目标，因此采用分步任务卡。

保留四个生活场景和输入、计算、输出的核心学习目标。每关显示“先想一想—做实验—搭流程图”三步；预测可错，实验自动记录，学生独立选择流程图描述和迁移判断。路口关先做入门观察样例，用两个信号按钮对比行人反应，去掉重复的动作选择。迁移题改为直接点击的短选项。声控灯默认独立模拟，现场实测作为可展开选项；模型的触发与延时规则仍驱动画面和记录。

## 验收与实现

- [x] 共享实验判定：`public/rules.js`提供实验检查项，界面与服务端使用同一证据条件。测试有效、缺失、错误来源记录。
- [x] 分步界面：`public/index.html`与`public/app.mjs`一次呈现当前任务，初始不展示未到的流程图/迁移题；前进按钮明确指出未完成事项。
- [x] 自动观察：红灯动作、声音状态、汉字完成和门位置产生真实记录；声音与门延时期间显示等待状态，不提前伪造结果。
- [x] 操作指引：常驻当前指令，完成动作后更新；提示仍按需逐级，不预填学习答案。流程图误答后聚焦需修订节点。
- [x] 恢复与兼容：旧草稿、首次预测、积分、教师隔离测试、20题重复考核和奖励继续使用原数据。
- [x] 浏览器走查：虚构学生无教师示例走通四关；错误—修订、刷新恢复、教师统计核对；1366×768与窄屏截图。
- [x] 更新使用说明、验收记录、当前本地服务和已授权GitHub仓库。

课堂效果仍需教师观察学生实际操作来校准，本次以流程可走通和界面可见性验证为准。
